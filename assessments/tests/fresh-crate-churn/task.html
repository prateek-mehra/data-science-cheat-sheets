Overview

Fresh Crate sells weekly meal-kit subscriptions. The retention team wants to know which customers are about to cancel. You have a snapshot of the customer base taken on 2026-06-30 and the full order history up to that date.

Work in the notebook on the right. The tasks build on each other, but each is graded separately. Tasks 1–3 are graded from the variables you leave in the notebook; Task 4 is graded from submission.csv. Variables are read from the live kernel when you submit, so make sure the cells that set them have been run.

Files

  • train.csv — one row per customer with the label churned (1 = cancelled within 60 days of the snapshot).
  • test.csv — the same columns without churned. You predict these.
  • orders.csv — every order placed by any customer: order_id, customer_id, order_date, amount, delivered_late, status.

Task 1 · Clean the customer table 15 pts

Load train.csv. Some rows were exported twice: remove rows that are exact duplicates across all columns. Then standardise plan to exactly Basic, Standard or Premium, and convert monthly_fee to a float.

Store, using the de-duplicated, cleaned training data:

  • task1_n_rows — the number of rows (int).
  • task1_plan_counts — a dict mapping each plan name to its row count, e.g. {"Basic": 10, ...}.
  • task1_mean_fee — mean monthly_fee, rounded to 2 decimals.

Task 2 · Features from the orders log 20 pts

Use only orders whose status is "completed". For every customer compute the number of completed orders, their total amount, and their late rate (the mean of delivered_late over their completed orders). Join these onto the cleaned training table from Task 1. Customers with no completed orders get 0 orders and 0 total spend; leave their late rate missing.

Store:

  • task2_no_orders — how many training customers have no completed orders (int).
  • task2_top_customer — the customer_id of the training customer with the highest total completed spend (int).
  • task2_late_rate_by_region — dict of region → average late rate across that region's training customers (customers with no completed orders are skipped), rounded to 3 decimals.

Task 3 · Churn analysis 15 pts

Using the cleaned training table with the Task 2 features, store:

  • task3_churn_by_plan — dict of plan → churn rate (mean of churned), rounded to 3 decimals.
  • task3_churn_rate_no_orders — the churn rate among customers with no completed orders, rounded to 3 decimals.

Add a markdown cell with one or two sentences on what these numbers suggest for the retention team.

Task 4 · Predict churn 50 pts

Train a classifier on the training data (logistic regression, a decision tree, random forest, gradient boosting — your choice) and predict churned for every customer in test.csv. Build the same features for the test set as for training.

Save submission.csv in the working directory with exactly two columns and one row per test customer:

customer_id,churned
610443,0
592892,1
...

churned must be 0 or 1. You can write the file from the notebook (sub.to_csv("submission.csv", index=False)) or upload it from the Files tab.

Scoring: F1 score on the positive class against hidden labels. 0 points at F1 ≤ 0.52 (the score of predicting that everyone churns), full points at F1 ≥ 0.70, linear in between. A short validation step (hold-out split or cross-validation) in your notebook is expected.
