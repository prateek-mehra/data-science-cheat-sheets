YOLO Architecture Cheat Sheet

A quick map of the major architectural shifts from YOLOv1 to Ultralytics YOLO26. Different teams share the YOLO name.

← Back to cheat sheets

The detector in three parts
StageJob
BackboneExtract visual features at several resolutions (coarse to fine).
NeckFuse feature maps so small and large objects can use context across scales; commonly FPN + PAN.
HeadPredict box coordinates and class scores; may be anchor-based or anchor-free, coupled or decoupled.
Post-processFilter boxes, traditionally with NMS. End-to-end designs can learn one prediction per object and skip NMS.

Fast vocabulary
TermMeaning
AnchorPredefined box shape used as a starting point for box prediction.
FPN / PANTop-down and bottom-up paths that combine features at multiple scales.
CSP / C3 / C2fFeature-processing blocks that split and recombine paths to balance reuse and compute.
SPP / SPPFPooling modules that add wider spatial context; SPPF is a faster sequential variant.
DFLDistribution Focal Loss: predicts a distribution over box-edge distances for refined localization.
NMSNon-Maximum Suppression: removes overlapping duplicate detections after prediction.

Lineage note: YOLOv5/8/11/26 are Ultralytics releases; YOLOv6, v7, v9, and v10 are distinct research branches. Version numbers do not imply a single uninterrupted author team or codebase.

The broad trend
  • Backbone: Darknet → CSP-based C3/C2f → C3k2 with attention.
  • Feature fusion: multi-scale prediction → FPN/PAN; SPP becomes faster SPPF.
  • Head: grid / anchor-based → anchor-free and decoupled.
  • Inference: NMS-based → learned end-to-end NMS-free variants.
  • Optimization: better training recipes and deployment-friendly graphs matter alongside layers.

Backbone: Cross Stage Partial (CSP)

The backbone is the feature extractor: edges → textures → shapes → object parts.

WordMeaning
StageGroup of layers at one feature-map resolution; each stage extracts deeper features and downsamples.
PartialSplit channels: only part A goes through the heavy conv blocks.
CrossOne path is transformed, the other skips the blocks; the two are concatenated and fused at the end of the stage.

Why introduced

  • Many layers learn similar features, so pushing every channel through every block is duplicate work.

Advantages

  • Lower FLOPs and memory, with similar or better accuracy; the skip path also gives a short gradient route.
  • Other common backbones: ResNet, DarkNet, EfficientNet.

Neck: FPN vs PAN
LayerResolutionCapturesGood for
DeepLowSemantics ("that looks like a cat")Classification, large objects
ShallowHighEdges, corners, textures, exact location ("a vertical edge")Small objects, localization
NeckIdeaNote
FPNTop-down: deep semantic features → upsample → add/concat with shallow features.Limitation: one-way, so deep layers never receive the shallow layers' precise localization.
PANFPN plus a bottom-up path: shallow features are downsampled and fused back into deep levels.Short path for localization signal; every scale gets both semantics and position.

Thresholds, IoU and mAP
Confidence thresholdEffect
HighFewer boxes kept → more false negatives (missed objects).
LowMore boxes kept → more false positives.
\[ \text{IoU} = \frac{|B_{pred} \cap B_{gt}|}{|B_{pred} \cup B_{gt}|} \qquad \text{Precision} = \frac{TP}{TP+FP} \qquad \text{Recall} = \frac{TP}{TP+FN} \]

A prediction counts as TP when its IoU with an unmatched ground-truth box of the same class is at or above the IoU threshold.

MetricMeaning
APArea under the precision-recall curve, traced by sweeping the confidence threshold (one class).
mAPMean of AP over all classes.
mAP@0.5mAP at IoU threshold 0.5 (lenient on box placement).
mAP@0.5:0.95Average of mAP at IoU = 0.50, 0.55, …, 0.95 (10 values); rewards tight boxes. COCO's main metric.
mAP summarizes detector quality across confidence thresholds and classes, so it does not depend on picking one threshold.

Tracking: SORT vs DeepSORT
PieceWhat it does
Kalman filterPredicts each track's next box from position + velocity; updated by the matched detection.
AppearanceDeepSORT crops each box and runs a re-ID CNN to get an embedding. SORT uses motion/IoU only, so IDs switch after occlusions or crossings.
ID assignmentCost combines motion distance (Mahalanobis to the Kalman prediction, used as a gate) and cosine distance between embeddings; Hungarian matching assigns detections to tracks. Unmatched detections start new IDs.

ResNet skip connections
ItemDetail
ProblemIn very deep nets the input signal (and gradient) fades as it passes through many non-linear layers; deeper can train worse.
SolutionAdd the block's input to its output: \( y = F(x) + x \).
H × W mismatchDownsample the shortcut with stride 2.
Channel mismatch1×1 convolution projection on the shortcut (\( y = F(x) + W_s x \)), or zero-pad the extra channels (no parameters).
AdvantagesKeeps the input signal strong through depth; if identity is best, the block only has to learn \( F(x) = 0 \), so the net chooses between a complex transform and passing info along. Makes 100+ layer nets trainable.

Face recognition embeddings

A ResNet maps each face to a 128-d embedding; faces match when their embeddings are close (dlib / face_recognition style).

DistanceUse
Euclidean (L2)Default: triplet loss trains the network to separate faces by this distance.
CosineOnly the angle matters; equivalent ranking to L2 after L2-normalising. dlib embeddings are not strictly normalised, so the two can differ.
Manhattan (L1)Not used: the network was not trained for L1 separation, and in high dimensions L1's diamond-shaped neighbourhoods distort the clusters.
\[ \cos\theta = \frac{\sum_i x_i y_i}{\sqrt{\sum_i x_i^2}\,\sqrt{\sum_i y_i^2}} \qquad d_{L1}(x,y) = \sum_{i=1}^{n} |x_i - y_i| \]
