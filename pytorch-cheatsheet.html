2. Autograd: who gets the blame?

Think of each tensor as a node in a computation graph. Every operation records its inputs and a local derivative. During backward(), PyTorch walks the graph in reverse and sends each node's incoming gradient through the chain rule. If a value reaches the result along multiple paths, those contributions add up.
OperationLocal gradient intuition
z = x + yOne extra unit of either input adds one unit to z: gradients are passed through unchanged.
z = x * yx gets scaled by y, and y gets scaled by x (product rule).
z = relu(x)Positive inputs pass the gradient through; negative inputs block it. At zero, PyTorch uses gradient zero.
import torch
import torch.nn.functional as F

a = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(-3.0, requires_grad=True)
c = torch.tensor(10.0, requires_grad=True)

d = a * b + c       # d = 4
e = F.relu(d)       # e = 4
loss = e * e        # loss = 16

loss.backward()     # seed d(loss)/d(loss) = 1, then chain backward
print(a.grad)       # -24: 2e * b = 8 * -3
print(b.grad)       # -16: 2e * a = 8 * 2
print(c.grad)       #   8: 2e * 1 = 8

# Inspect the graph PyTorch built (names vary by operation)
print(loss.grad_fn)       # MulBackward0
print(loss.grad_fn.next_functions)

# Gradients accumulate by default; clear them before another pass
for x in (a, b, c):
    x.grad = None
This is the same bookkeeping as a tiny scalar Value engine: each operation remembers its parents and local backward rule; the final result starts with gradient 1; a reverse topological pass accumulates contributions into leaves. PyTorch builds and traverses that graph automatically. Leaf tensors with requires_grad=True receive gradients in .grad; intermediate tensors usually do not unless you call .retain_grad(). For vector outputs, provide an upstream gradient or reduce to a scalar first, for example scores.sum().backward().

3. The update rule - all of gradient descent

SymbolMeaning
w ← w - η · ∇L(w)Step the weights downhill, against the gradient of the loss
wModel parameters
η (lr)Learning rate - how big a step
∇L(w)Gradient of the loss at the current weights - the uphill direction
Every optimizer (momentum, Adam, ...) is a variation on how this step is computed and scaled. See the ML Optimizers sheet for that ladder.

4. Batch vs stochastic vs mini-batch GD

Batch GD

Data per updateThe whole dataset
Updates / epoch1
GradientExact for the full training loss - deterministic given the data
In PyTorchOne pass over the full set per step

Stochastic GD (SGD)

Data per update1 sample
Updates / epochN
GradientSingle-sample estimate - noisy; the noise can bounce out of shallow minima
In PyTorchDataLoader(ds, batch_size=1)

Mini-batch GD

Data per updateB samples, e.g. 32-256
Updates / epochceil(N / B) - the last batch can be partial; drop_last=True makes it floor(N / B)
GradientAverage over B samples - less noisy than one sample, cheaper than the full set; the practical default
In PyTorchDataLoader(ds, batch_size=B, shuffle=True)
Same rule, three choices of how much data backs each gradient estimate. The optimizer is batch-size agnostic: torch.optim.SGD.step() updates from whatever gradient the last backward() produced. The batching you feed it - one sample, B samples, or the whole dataset at once - is what makes the run stochastic, mini-batch or full-batch.

5. The training loop (mini-batch)

from torch.utils.data import DataLoader, TensorDataset

loader  = DataLoader(TensorDataset(X, y),
                     batch_size=32, shuffle=True)
loss_fn = torch.nn.CrossEntropyLoss()
opt = torch.optim.SGD(model.parameters(), lr=0.01)

for epoch in range(10):
    model.train()
    for xb, yb in loader:
        opt.zero_grad()   # clear old gradients
        loss = loss_fn(model(xb), yb)
        loss.backward()   # compute gradients
        opt.step()        # apply the update
The same four lines drive almost every PyTorch model: zero, forward, backward, step. Skipping zero_grad() accumulates gradients across batches.

6. A basic CNN

import torch.nn as nn

class SmallCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            # input: 1x28x28
            nn.Conv2d(1, 16, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),      # -> 16x14x14
            nn.Conv2d(16, 32, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),      # -> 32x7x7
        )
        self.classifier = nn.Linear(32 * 7 * 7,
                                    num_classes)

    def forward(self, x):
        x = self.features(x)     # Nx32x7x7
        x = torch.flatten(x, 1)  # Nx(32*7*7)
        return self.classifier(x)

model = SmallCNN()   # input: Nx1x28x28

nn.MaxPool2d(2)Halves height and width, keeps the strongest response

8. Gotchas

  • Forgetting opt.zero_grad() silently accumulates gradients across batches.
  • model.train() vs model.eval() - dropout and batchnorm behave differently in each mode.
  • Inputs are N x C x H x W: a single 28x28 grayscale image becomes (1, 1, 28, 28) via img[None, None].
  • CrossEntropyLoss takes raw logits and integer class labels - no softmax, no one-hot.
  • Model and batch must sit on the same device, or the forward pass errors.
  • Use loss.item() for logging; keeping the tensor alive holds the whole graph in memory.
